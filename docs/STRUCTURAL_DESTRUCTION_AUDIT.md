## Common removal chain

1. `IsoGridSquare.transmitRemoveItemFromSquare(IsoObject obj, boolean safelyRemove)` checks square membership. On the server it resolves eligible multi-square objects through IsoObjectUtils.getAllMultiTileObjects, then invokes GameServer.RemoveItemFromMap for the resolved objects. In SP it uses RemoveTileObject. Do not assume server and SP enter the identical low-level implementation.
2. [GameServer.RemoveItemFromMap](evidence-followup/decompiled/zombie/network/GameServer.java#L3023) captures coordinates/current object index, sends RemoveItemFromSquare to relevant clients, then invokes the packet's local removal helper. Native network identity here is a square/index, not a stable crash-component identifier.
3. [RemoveItemFromSquarePacket.removeItemFromMap](evidence-followup/decompiled/zombie/network/packets/RemoveItemFromSquarePacket.java) sets previous IsoRegions flags for non-inventory objects, handles radio associations/table render offsets, fires OnObjectAboutToBeRemoved, removes world/square membership and recalculates neighbors. Non-inventory removal also checks roof coverage, MapCollisionData, PolygonalMap2, ServerMap.physicsCheck, IsoRegions and generators. Special double/garage objects can enter an additional safe multi-object removal branch.
4. Client `processClient(UdpConnection)` delays removal if the square is absent; otherwise it looks up the current index and calls `sq.RemoveTileObject(o, isDestroyAsMultiTileObject)`. That square path invalidates render chunk state, recalculates neighbors, roof checks and lighting/LOS, emits removal events and updates collision/navigation/regions. Do not add a second unconditional removal/recalculation after a server transmission on the assumption that transmission was network-only.
5. Generic [RemoveTileObject](evidence-followup/decompiled/zombie/iso/IsoGridSquare.java) is not the same operation as a specialized destroy: it does not automatically implement every container spill, drop, attachment or window state transition.

`RecalcAllWithNeighbours(boolean, GetSquare)` loops x/y/z offsets -1..1 around the changed square and recalculates navigation and cardinal neighbor pairs (IsoGridSquare.java:4533-4571). That is a minimum local dependency set, not an upper bound on all effects. `IsoCell.checkHaveRoof(int,int)` scans the same x/y column from z=31 down to 0; solidfloor or BlockRain changes roof coverage below and can trigger more neighbor recalculation. A one-object deletion can therefore affect multiple levels.

`IsoRegions.squareChanged(IsoGridSquare, boolean)` is non-client work: it compares calculated flags and queues a region worker job (:334-347). This is not a synchronous guarantee that lighting, region enclosure, weather and all clients have settled before returning. MapCollisionData.squareChanged and PolygonalMap2.squareChanged are notification paths, not runtime proof of correct navigation. IsoGridOcclusionData.SquareChanged invalidates its shared cache; cutaway also depends on renderer, building/room/sprite properties and client state.

### Cutaway, room and weather chain

[IsoObject.invalidateRenderChunkLevel](evidence-followup/decompiled/zombie/iso/IsoObject.java#L5528) invalidates its owner square and a distinct render square if present. IsoGridSquare.invalidateRenderChunkLevel (:9807) delegates to its chunk; [IsoChunk.invalidateRenderChunkLevel](evidence-followup/decompiled/zombie/iso/IsoChunk.java#L5181) invalidates that level for each local player's render levels. This expands rendering dependencies beyond the object's nominal coordinate.

[FBORenderCutaways](evidence-followup/decompiled/zombie/iso/fboRenderChunk/FBORenderCutaways.java) separately checks the player's room, exterior-wall caches, adjacent chunk counters, occluded rooms and elevated floors using local camera/player data. Its squareChanged method (:198) clears per-player checkSquare state. Methods named CalculateBuildingsToCollapse/shouldHideElevatedFloor concern rendering and are not evidence of a safe physical building-collapse simulation. The inspected common deletion chain's dirty/cache notifications do not prove that every cutaway or orphan/sloped-surface cache settles correctly after an arbitrary corridor.

IsoGridSquare.getRoom (:7992) returns its stored room when roomId is valid; getBuilding derives from that room. IsoRoom.addSquare/removeSquare/refreshSquares and IsoBuilding's definition/room membership are distinct paths. No complete room-definition reconstruction was demonstrated from generic wall removal; region enclosure and map room identity must not be equated.

[WeatherFxMask](evidence-followup/decompiled/zombie/iso/weather/fx/WeatherFxMask.java) consults player/building membership and IsoWorldRegion fog-mask connections (:398-417), alongside interior/solidfloor/exterior context. A roof coverage bit or collision update is not proof of natural rain/fog masking. Dedicated replication plus per-client cutaway/weather tests remain mandatory. The renderer and weather snapshots add source context, not runtime validation.

## Vanilla destruction policy details

[ISDestroyStuffAction.lua](evidence-followup/installed/media/lua/shared/TimedActions/ISDestroyStuffAction.lua) shows why direct wall deletion is incomplete: same-square attachedW/attachedN fixtures, adjacent-square attachedE/attachedS fixtures, opposite-side barricades, curtain returns, sheet ropes, stairs, doors and graves are handled separately. CornerNorthWall/CornerWestWall properties select a replacement sprite so the unstruck edge is retained (:309-335). These are native/vanilla policy observations only; no copied implementation was put into mod code.

The precomputed footprint must close over every linked object and all spawned/dropped results before any commit. A stable operation manifest cannot merely store (x,y,z,index), because indices shift and vanilla sledge/corner operations can replace object identity. Persist a verified immutable precondition describing the specific owner, edge, sprite/property identity and any component linkage; if it no longer matches, cancel/quarantine. Unknown wall orientation or mixed structures must be rejected.

Safehouse membership is available, but permission to enter a claimed safehouse is not absence of a claim. Unclaimed modified vanilla buildings and historical player construction remain unproved. `getPlayerBuiltFloor` and instanceof(IsoThumpable) are not adequate provenance tests. Protect both sides, the roof column and all dependent objects; any uncertainty rejects the candidate.
