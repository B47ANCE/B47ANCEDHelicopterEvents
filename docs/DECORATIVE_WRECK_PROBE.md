# Decorative wreck diagnostic

Current implementation checkpoint: 0.1.0-dev.6, 2026-10-17. Additive diagnostic within the pending initial 0.1.0 development line; no stable API, gameplay release or save migration claim. The user approved the bounded implementation and selected **8871,8253**, interpreted as outdoor ground **z=0**, with the upright optimized wreck. The [preceding source audit](STATIC_WRECK_API_AUDIT.md) remains a dated review record. The implementation does not clear its production NO-GO findings.

## Implemented boundary

`B47HE.EnableDecorativeWreckProbe` is a server-authoritative boolean, default false, on the localized Decorative Wreck Diagnostic sandbox page. Missing, false or malformed values deny placement. It is independent of audio flights and the read-only radio probe. Existing saves need no mod-data migration: an absent option fails disabled. Disabling does not remove or alter an existing native object.

There is **no automatic placement**. OnServerStarted creates an in-memory handler only. OnTick on the client marks connection readiness only. Startup, streaming, reconnect, restart, sandbox enablement and time passage never send placement requests or create objects. No scheduling, chunk-loading, removal, regeneration or retry hook exists. No modData/GlobalModData ledger, containers, inventory operations, loot, salvage, sounds, attraction, destruction, collider or floor generation is added.

An explicit developer request sends only protocol version, bounded nonce and synchronized client timestamp. The server receives the connection-associated player through the existing OnClientCommand path; it checks dedicated mode and that player's native `isAccessLevel("admin")`, living state and proximity. No client identity, role, coordinates, mesh, variant, clearance, inventory or authorization flags are accepted. Malformed/extra fields, old/future timestamps beyond 2 seconds, requests within the 2-second per-player rate limit and a repeated last accepted nonce are rejected. A refused request cannot be replayed into placement merely by changing settings. Clock failure/regression halts the handler.

The live server player must be on z=0 and within 20 tiles of the fixed anchor, while all moving occupants must be outside the checked test area. Usually stand **9-20 tiles away**, outside the 17x17 square. This deliberately permits visible placement in a disposable diagnostic save; it does not satisfy or bypass strict unseen random-crash requirements.

The server checks a fixed **17x17 ground square**, x=8863..8879, y=8245..8261. Every square must be available through the existing server lookup, have a chunk and a floor, be outside with no room/building or solid/solidtrans flag, and contain exactly that floor in its ordinary object list. Special objects, world items, moving objects and static moving objects must all be absent. The server performs two bounded inspections and compares square/floor references, including a final settings/player check before insertion. No terrain, plants or obstructions are removed. A refusal can be manually retried with a new request only while no mutation attempt has been consumed; there is never an automatic retry.

These are explicit native square-list checks, **not** a proved full 3D/vehicle/mesh clearance, load-worker/admission barrier or reservation service. Native listeners, streaming races, vehicles, upper geometry and nearby interactions remain dedicated runtime gates. The Lua scan runs only for an authorized manual request, at most twice per accepted attempt (578 Lua square lookups, excluding native insertion work), not every frame or over the world. Initial scale is an uncalibrated authoring fixture, not a physical/collision promise.

Immediately before native construction, the server consumes a process-local attempt latch. It creates one ordinary `IsoObject` with the mod's existing B47 icon texture as a non-tile fallback, selects `B47HE.WreckProbeUprightPlacement`, rechecks preconditions, inserts once with `AddTileObject`, checks the resulting local membership, and calls `transmitCompleteItemToClients` once. Client Lua never constructs world objects. No vanilla method or sprite/model definition is monkey-patched. No native Java dependency is introduced.

The latch survives duplicate requests and repeated OnServerStarted callbacks for the loaded module. It is never cleared after removal, disable/re-enable, an insertion error, publication error or timeout. Adapter exceptions halt this diagnostic and print an internal diagnostic message; existing audio/radio adapters are separate. No automatic rollback, retransmission or recovery is attempted after uncertainty. `published` means the native publication call returned, **not** that any client acknowledged receipt, rendered the mesh or durably saved it.

## Persistence and reconnect semantics

The ordinary object relies solely on native chunk save/load, including its SpriteModel name and original constructor spriteName. The existing complete-object/native chunk paths own replication and late reconstruction. There are no custom per-client world spawn/replay messages, and reconnecting clients submit no automatic request. Temporary client request state is cleared on connection changes; pending requests expire after 5 seconds with no retry, and correlated results expire 5 seconds after reception. Nonce counters are not reset by reconnect events within the same Lua process.

The attempt latch is **not durable** and there is no exactly-once-across-restarts claim. A restarted handler is idle; a new explicit admin request is required to attempt anything. If the native object survived, the nonempty test area refuses another object. If it was removed or lost, the mod never restores it automatically. A later explicit manual request in a restarted disposable session may make a new diagnostic attempt after checking the area; that is operator intent, not recovery from an inferred absent marker. Normal graceful saves, hard interruptions, stale chunk snapshots and native removal still need real dedicated evidence. Never use this mechanism for valuable cargo, production crash identity or replay guarantees.

## Local assets and definitions

The source definition `media/scripts/B47HE_WreckProbe.txt` contains exactly one static `model` and one named `spriteModel`. Mesh: `B47HE/wreck_probe_upright.glb`; separately named texture: `media/textures/B47HE/wreck_probe_upright.png`. The mesh is an exact copy of the optimized 24,969-triangle GLB; the PNG has the same decoded RGB pixels and 2048x2048 dimensions as its embedded base-color image. The other embedded maps remain untouched but are not promised to bind to PZ's shader. `scale=6`, `undoCoreScale=true` and zero placement transforms are an initial fixed diagnostic fixture; native axis, scale, ground contact and appearance are NOT TESTED. No rig or animated parts.

`scripts/prepare_wreck_probe_assets.py` creates those two files **inside the repository source tree only**, from the retained optimized authoring checkpoint, and refuses differing destinations. It never copies to an installed mod folder or packages/uploads anything. [Asset receipt](../assets/crash-sites/WRECK_PROBE_ASSETS.json) records exact input/output hashes and conversion provenance. Originals, editable Blender work and prior exports remain unchanged. Asset bytes are local/Git-ignored: supplied-model redistribution provenance remains unresolved. A public clone contains definitions/recipe/receipt, not those binaries. The server's native `fileExists` and definition checks deny requests when local files/definitions are absent; existence is not import/material readiness or a cryptographic runtime content check. Distribution remains blocked pending provenance and explicit approval.

The fallback path is the existing, unchanged `media/ui/B47_ICON_SMALL.png`. The constructor uses the engine's named-sprite lookup, which can create an ordinary texture-backed sprite for that path. It is a recognizable fallback marker, not a 2D helicopter or proof of 3D rendering. No tile flags, furniture identity, PhysicsMesh or vanilla sprite mapping is copied into it. Shader/FBO failures can still leave this marker or delayed rendering; verify native behavior before expanding scope.

Configuration assessment: enablement is meaningful shared behavior and therefore a localized server sandbox setting. The user-selected coordinates, one fixed variant/transform, ground level, conservative scan bound, request size/rate/expiry limits and session latch are internal diagnostic-fixture/safety constants. Exposing them as general crash balance/placement options would expand this bounded slice. No option disables authority, inspection or exception handling.
